01
The core idea

A problem inside a problem.

To understand recursion, start with its two ingredients. One keeps things moving. The other tells us when to stop.

THE BASE CASE⊙

The answer you already know.

A case so simple that you can solve it directly, without asking the same question again. It anchors the definition and gives the computation a place to stop.

factorial(0) = 1
No smaller problem needed.
THE RECURSIVE STEP

A smaller version of the question.

Express the answer using the same problem on a smaller input. Combine that smaller answer with the work at this step to solve the original problem.

factorial(n) = n × factorial(n − 1)
Same question. One step closer.
→The missing ingredient? Progress toward the base case. A stopping rule only helps if you reach it.
02
In mathematics

Define the next answer with the last.

A recursive definition builds new values from values already defined.

Take factorial, for example.

The factorial of a nonnegative integer n, written n!, is the product of the integers from 1 through n. For zero, the empty product is 1.

Instead of writing out every multiplication, we can define it recursively:

n! ={
1if n = 0
n · (n − 1)!if n ≥ 1
Domain: n ∈ {0, 1, 2, 3, …}
Unpacking 4!, one layer at a time
4!= 4 × 3!
=4 × 3 × 2!
=4 × 3 × 2 × 1!
=4 × 3 × 2 × 1 × 0!
=4 × 3 × 2 × 1 × 1BASE CASE
4! = 24
Why is this well-defined? Every recursive step reduces a nonnegative integer by 1, so it eventually reaches 0. Mathematical induction can prove properties of the resulting values using the same base-and-step structure.

In computer science

When a function calls itself.

The mathematical definition becomes a program. Each call waits for its smaller problem to return an answer.

Base caseRecursive step
1

Check for the simplest case.

When n === 0, return 1 immediately. This call makes no further recursive call.

2

Delegate the smaller problem.

Call factorial(n - 1). The current call pauses its multiplication until that call returns.

3

Let the answers travel back.

The call stack holds the waiting function calls. Starting at the base case, each call returns its result to the caller, which finishes its own work.

05
Beyond factorial

Small pattern. Big possibilities.

Recursion is especially useful when the structure of a problem is itself recursive.

Explore nested structures.

A folder contains files and more folders. A tree contains smaller trees. Apply the same operation to each child, stopping at a leaf.

Folders · syntax trees · nested data

Divide, solve, combine.

Merge sort splits a list into halves, sorts each half recursively, then merges them. A list of zero or one item is already sorted.

Merge sort · binary search
!

Know the tradeoffs.

Deep recursion can exhaust the call stack. Repeated subproblems can waste work. Loops, an explicit stack, or memoization may be a better fit.

Naive Fibonacci repeats subproblems

Same problem. Smaller input. A place to stop.

For factorial, recursion and a loop both take O(n) time. This recursive version also uses O(n) stack space; a loop can use O(1).
